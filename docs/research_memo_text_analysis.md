# 研究メモ｜テキスト分析：作業日誌の「困りごと」を数え、原文で確かめる

テキスト分析 第1回「次回までの課題 3／研究メモ（200〜300字）」の提出版と、その実装の対応表です。

## 研究メモ（改訂版・276字）

> 関心分野は、小規模農業法人へのAIエージェントの導入である。テキストは、従業員が毎日記入する作業日誌の自由記述（1日1件）とする。問いは「作業上の困りごとが、どの作業や時期に、どのような言葉で書かれているか」である。まず「遅れ」「故障」「人手」を含む日誌を作業別・月別に数え、該当した原文を読む。注意点は四つある。第一に、語の出現回数と日誌の件数を区別し、分母を示す。第二に、「故障はなかった」のような否定も一致するため、原文で確かめる。第三に、「壊れた」などの言い換えは漏れる。第四に、氏名や取引先名を匿名化してから分析し、外部のAIには入力しない。

字数は `len()`（句読点・括弧も1文字）で数えています。ノートブックの最後のセルが 200〜300字を `assert` で確かめます。

## 4項目

| 項目 | 内容 |
|---|---|
| 関心分野 | 小規模農業法人へのAIエージェント導入（どの作業から入れるか） |
| テキスト | 従業員の作業日誌の自由記述（1日1件）。分析の前に匿名化。本リポジトリでは架空36件で手順を試した |
| 問い | 作業上の困りごとが、どの作業・時期に、どのような言葉で書かれているか |
| 注意点 | 回数≠件数（分母を示す）／否定の一致を原文で確認／言い換えの漏れ／匿名化と外部AI不使用 |

## 実装（3段構え）

| 段 | ノートブック `notebooks/text_analysis_work_diary.ipynb` | 画面 `pages/5_🔤_作業日誌テキスト分析.py` |

## 架空データでの結果（手順の確認用。実態の主張ではない）

- 分母36件。「遅れ」14回・14件、「故障」**8回・7件**（D10に2回）、「人手」9回・9件。
- 一致した30組（日誌×語）を人が読むと、困りごと18・否定9・保留3。
- 素朴な規則（「ない」があれば否定）の一致は **60%**。「人手が足り**ない**」を否定と誤る。
- 規則2（語の直後の形を語ごとに判定）の一致は **87%**。残る4組は推測の打ち消し・対象が作物・予測・解消の報告で、規則では決められない。
- 言い換えで4件が新たに見つかり、うち3件が困りごと。

## 限界と次の一手

1. 判定者が1人。2人が独立に読み、κ係数を確かめる。
2. 規則2と言い換え辞書は、この36件を見て作った後付け。別の月・別の法人の日誌で一致率を確かめる。
3. 件数は重要度ではない。日誌には「止まった時間」が書かれていない。
   → 次の一手は分析ではなく**日誌の書式の改訂**：自由記述は残し、「止まった時間（分）」「影響（出荷・作業・品質）」の2欄を足す。
4. 実データは匿名化しても、原文を外部の生成AIに貼らない。ノートブックは手元かColabで動かす。
